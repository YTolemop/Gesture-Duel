# 遊戲玩法說明與完整數值設定

> 本部分的雙人規則是 PVP 基準；新增模式參閱本整合文件第三部分。文件修訂不表示程式已製作或驗證。

## 摘要

以手勢操作的橫向戰鬥遊戲，包含雙人 PVP、技能圖鑑、假人練習與 PVE 一命連戰。任何使用者皆可建立 PVP 房間並以房號邀請另一位玩家；每房紅藍各一位玩家及一個觀戰席位。兩位玩家各自使用筆電與鏡頭，以自己訓練的靜態手勢控制角色。

所有人使用相同基礎角色，不需要選角，而是在開戰前選擇攻擊、防禦、控制技能與大招。戰鬥以遠程法術互轟為主，搭配近戰普攻、閃避與格擋，透過距離、出招時機與氣量管理擊敗對手。

> 單手即可完成所有操作；學員也可自選雙手訓練與操作，設計自己的施法方式。
>
> 本文件為 numeric-v2-2026-10-08 數值版，已依數值審查調整傷害、範圍、速度、部分控制與防禦參數；生命、場地與基本操作保留。計算和獨立模型檢查見 numeric_balance_audit.md，不代表已完成真人對戰平衡。
>
> 對戰概念參考《Street Fighter 6》，技能、具體規則與本文件新增參數為本次原創設計。

## 一、對戰規則與地圖

### 座標與尺寸定義

- 地圖邏輯尺寸固定為 $1920\times1080\,\mathrm{px}$，固定側視角，鏡頭不跟隨、不縮放、不震動。
- 螢幕不同解析度時等比例縮放，必要時加黑邊；不得改變可見場地範圍或角色碰撞比例。
- 左上角為原點，向右為 $+x$，向下為 $+y$。
- 角色座標 $(x,y)$ 指腳底中央；地面站立時 $y=900$。
- 下文尺寸皆為邏輯像素；矩形尺寸寫作寬 $\times$ 高，圓形寫半徑。
- 「前方」指該次出招鎖定的方向。圓形／矩形判定以真實碰撞框相交為準，並非只檢查角色中心。
- 判定區與角色框只有邊界接觸、不產生面積重疊時，不算命中；地面領域另依腳底區段判定。

### 地圖數值

| 項目 | 數值／規則 |
| --- | --- |
| 地圖尺寸 | $1920\times1080\,\mathrm{px}$ |
| 地面高度 | $y=900$；地板裝飾區為 $900\le y\le1080$ |
| 左右場界 | $x=96$ 與 $x=1824$，可用場寬 $1728\,\mathrm{px}$ |
| 站立角色中心範圍 | $128\le x\le1792$，碰撞框不可越出場界 |
| 角色可到達區域 | 上方不設平台；只有一層地面，無坑洞、障礙、傷害地形 |
| 紅方出生點 | $(480,900)$，面向右 |
| 藍方出生點 | $(1440,900)$，面向左 |
| 出生中心距離 | $960\,\mathrm{px}$ |
| 賽前倒數 | $3\,\mathrm{s}$；此時禁止操作，局時計時與大招解鎖尚未開始 |
| 普通飛行物邊界 | 飛行物完全離開場界或畫面上界即消失；碰到地板也消失，地走焰除外 |
| 瞬移／推拉邊界 | 按角色碰撞框限制位置，不能越出場界，不產生撞牆傷害 |

### 場地與角色規則

- 兩名法師在同一座平面競技場中對戰，以紅、藍兩方區分；生命、移動速度與大小相同。
- 待機、移動、蹲下、空中與格擋時，自動面向對手。中心橫座標相同時保留上一個方向。
- 出招開始時鎖定方向與施法位置，直到收招結束；生成後的法術不會自動轉向或追蹤。
- 玩家可左右移動、跳躍與蹲下。雙方都在地面時不能直接穿過對手；任一方在空中時不作角色間的實體阻擋，因此可跳過換邊。
- 空中仍保留受擊碰撞框，可以被法術命中。落地重疊時按落地者來向移到最近合法位置，不推動另一名角色；位置受場界限制。
- 普攻、技能與大招只能在地面使用；施法時自動解除蹲姿，改用站立碰撞框。
- 出招準備與收招時不能走動、跳躍、蹲下或格擋；位移技能依其效果移動。
- 空中不能施法、普攻或格擋；落地不附加額外收招，但仍須滿足僵直與其他限制。
- 格擋使用玩家指定手勢，與是否後退無關。

### 勝負方式

- 採 **BO1 單局決勝**，每場只打一局；每人生命為 $1000$，每局 $90\,\mathrm{s}$。
- 對手生命歸零即獲勝；時間結束時，剩餘生命較多者獲勝，護盾不列入比較。
- 若生命相同，加賽 $15\,\mathrm{s}$，延續原有生命、氣量、效果與冷卻；仍平手則以相同配置重賽該局。
- 若雙方同時生命歸零，該局平手，以相同配置重賽。
- 開局或平手重賽時，重置生命、氣量、位置、全部效果、場上物件、技能冷卻與大招解鎖時間；加賽不重置。
- 同一模擬步內的傷害與致死一起結算，再判定勝負，不因紅藍處理順序產生優勢。
- 最後一個有效戰鬥步完成後，先判定生命歸零，再判定時間結束；超過局時不再結算新的攻擊。

## 二、角色與移動數值

### 基礎角色

| 項目 | 數值／規則 |
| --- | --- |
| 初始／最大生命 | $1000$；無自然回血 |
| 初始／最大氣量 | $6$ 格 |
| 站立碰撞框 | $64\times144\,\mathrm{px}$，範圍為 $[x-32,x+32]\times[y-144,y]$ |
| 蹲下碰撞框 | $64\times80\,\mathrm{px}$，範圍為 $[x-32,x+32]\times[y-80,y]$ |
| 空中碰撞框 | 與站立相同，不提供空中縮身 |
| 站立角色圖像框 | $96\times168\,\mathrm{px}$，腳底中央為錨點；飾品不加入碰撞 |
| 蹲姿角色圖像框 | $96\times96\,\mathrm{px}$ |
| 水平走速 | $320\,\mathrm{px/s}$，左右相同，無衝刺 |
| 加速／減速 | 有效方向輸入時立即達目標速度；解除時立即停止，無地面慣性 |
| 蹲下／起身時間 | 各 $0\,\mathrm{s}$，在下一個有效模擬步切換 |
| 蹲下限制 | 不可水平移動；可直接改成格擋、跳躍或出招，切換後使用對應姿態 |
| 格擋碰撞框 | 固定使用站立框；蹲下切換格擋時立即站起 |
| 空中水平操控 | 基礎速度同為 $320\,\mathrm{px/s}$；緩速只乘在水平速度上 |

### 跳躍數值

| 項目 | 數值／規則 |
| --- | --- |
| 重力 | $2800\,\mathrm{px/s^2}$，方向向下 |
| 起跳垂直速度 | $-1120\,\mathrm{px/s}$ |
| 上升至最高點 | $0.4\,\mathrm{s}$ |
| 最大腳底離地高度 | $224\,\mathrm{px}$，最高點腳底 $y=676$ |
| 最高點角色頭頂 | $y=532$ |
| 正常滯空時間 | $0.8\,\mathrm{s}$，無二段跳、無變高跳 |
| 最大無緩速水平跳距 | $256\,\mathrm{px}$，需整段保有同向空中水平輸入 |
| 再次起跳 | 落地後可接受新的跳躍觸發，沒有額外跳躍冷卻 |

- 起跳時，可沿用最近 $0.5\,\mathrm{s}$ 內最後有效左右方向，初始水平速度為同向 $320\,\mathrm{px/s}$，再計入緩速。
- 持續維持 `JUMP` 可維持上述跳躍方向；沒有近期方向時原地跳。
- 空中切換 `MOVE_LEFT`／`MOVE_RIGHT` 即改變水平速度；切換 `NONE` 或其他非移動標籤即停止水平移動，垂直跳躍仍自行完成。
- 跳躍被命中不取消垂直速度與重力；受擊僵直期間停止主動水平移動，另有強制位移時依其數值執行。
- 定身時不可起跳；地面型定身技能不會將已在空中的角色強制拉回地面。

## 三、賽前技能配置

普通技能分為攻擊、防禦、控制三類，每類五種；大招同樣分三類，每類三種。

| 裝備欄位 | 選擇方式 | 主要用途 |
| --- | --- | --- |
| 攻擊技能 | 從五種攻擊技能中選一種 | 遠程輸出、壓迫對手 |
| 防禦技能 | 從五種防禦技能中選一種 | 保護自己、處理攻勢或脫離危險 |
| 控制技能 | 從五種控制技能中選一種 | 限制移動、改變距離、創造機會 |
| 大招 | 從九種大招中選一種 | 關鍵時刻進攻、防守或改變戰局 |
| 近戰普攻 | 所有人固定擁有 | 不耗氣的近距離攻擊 |

### 選技順序

開賽前抽籤決定 A、B，依 **ABBAABBA** 的順序選技；紅藍席位不影響抽籤。

| 順位 | 玩家 | 選擇內容 | 公開方式 |
| --- | --- | --- | --- |
| 第一手 | A | 大招 | 隱藏 |
| 第二手 | B | 大招 | 隱藏 |
| 第三手 | B | 普通技能 | 立即公開 |
| 第四手 | A | 普通技能 | 立即公開 |
| 第五手 | A | 普通技能 | 立即公開 |
| 第六手 | B | 普通技能 | 立即公開 |
| 第七手 | B | 普通技能 | 立即公開 |
| 第八手 | A | 普通技能 | 立即公開 |

- 普通技能可自由決定類別先後，最終必須攻擊、防禦、控制各一招。
- **普通技能不能重複選取，大招允許雙方選擇相同招式。** 共通普攻不受此限制。
- 雙方先依順序私下鎖定大招，不公開、不因重複重選。
- 大招在首次接受施放指令時公開；即使準備期間被打斷，也已公開。此後名稱與冷卻可供觀戰。
- 隱藏大招資訊只傳給本人，不傳給對手或主持人觀戰端。
- 開戰後不得更換技能，平手重賽沿用配置；重賽不把已公開的大招重新隱藏。
- 選技每手不設自動超時，主持人確認雙方準備完成後才開戰。

> 手勢對應技能欄位。例如攻擊技能從火球術換成地走焰，仍沿用攻擊手勢，不必替每個法術重新錄製。

## 四、單手、雙手與輸入規則

學員可自行設計單手或雙手姿勢。所有移動、格擋、普攻、技能與大招皆可透過單手完成。

雙手可分工選擇動作，或採集雙手組合資料，但共用辨識器最終每次只輸出一個標籤。雙手組合以固定128維特徵交給同一KNN，最終只產生一個指令；可選濾波仍只處理這個分類結果，不另建立兩手同時出招的輸出通道；不能靠雙手同時施放兩招，也不能一邊格擋一邊攻擊。

### 固定指令

| 類別編號 | 輸出標籤 | 操作 | 觸發方式 |
| --- | --- | --- | --- |
| $0$ | `MOVE_LEFT` | 左移 | 持續 |
| $1$ | `MOVE_RIGHT` | 右移 | 持續 |
| $2$ | `JUMP` | 跳躍 | 一次；空中維持時保留起跳方向 |
| $3$ | `CROUCH` | 蹲下 | 持續 |
| $4$ | `BLOCK` | 格擋 | 持續 |
| $5$ | `NORMAL_ATTACK` | 近戰普攻 | 一次 |
| $6$ | `ATTACK_SKILL` | 攻擊技能欄位 | 一次 |
| $7$ | `DEFENSE_SKILL` | 防禦技能欄位 | 一次 |
| $8$ | `CONTROL_SKILL` | 控制技能欄位 | 一次 |
| $9$ | `ULTIMATE` | 大招欄位 | 一次 |
| 無 | `NONE` | 無有效手勢／解除輸入 | 停止持續操作 |

- 數字是資料類別編號，不要求真人一定比出數字姿勢；辨識器對外傳送上述固定標籤。
- 單手與雙手使用相同技能、傷害、冷卻與氣量規則；開戰前完成設定。
- 一個出招手勢維持不放只觸發一次。再次出招需先解除該手勢，再重新做出指令；有效切換到其他標籤也算解除。
- 有效標籤解除／切換需持續 $0.1\,\mathrm{s}$ 才重新武裝原本的一次性指令，避免單張誤判造成連發；此確認不延後停止持續操作。
- 持續移動與格擋不需要反覆重做手勢；角色暫時不能操作時，該持續意圖保留，限制結束後依最新標籤恢復。
- 一次性指令在不合法時直接拒絕，不儲存、不在稍後自動施放；再次嘗試需重新觸發。
- KNN 與學員濾波的確認時間由學員調整，不計入技能準備；競技場不額外替每次有效施法加入統一辨識等待。
- 玩家辨識器至少每 $0.1\,\mathrm{s}$ 回報最新狀態。超過 $0.5\,\mathrm{s}$ 未收到輸入即視為 `NONE`；不替玩家補送舊操作。
- 鏡頭無手、讀取失敗或無可信分類時輸出 `NONE`；不把沒有手強制分成十個動作之一。

## 五、普攻、格擋與閃避

### 近戰普通攻擊

所有人都有免費法杖揮擊，不消耗氣，只能命中近距離目標。

| 項目 | 數值／規則 |
| --- | --- |
| 傷害 | $70$ |
| 耗氣 | $0$ 格 |
| 出招準備 | $0.25\,\mathrm{s}$ |
| 有效揮擊窗口 | $0.1\,\mathrm{s}$ |
| 收招 | 有效窗口結束後 $0.35\,\mathrm{s}$ |
| 完整動作時間 | $0.7\,\mathrm{s}$ |

- 有效窗口結束前角色仍視為出招；受擊僵直會取消尚未結束的揮擊判定。

### 格擋

指定格擋手勢進入防禦，維持時不能移動、跳躍或施法。基礎格擋同時防禦兩側，不因換邊失效。

| 項目 | 數值／規則 |
| --- | --- |
| 進入／解除準備 | $0\,\mathrm{s}$，下一個有效模擬步切換 |
| 成功格擋減傷 | $80\%$，承受原傷害的 $20\%$ |
| 命中扣氣 | $0.5$ 格，最低扣至 $0$ 格 |
| 防禦停頓 | $0.15\,\mathrm{s}$，僅限制防守者操作，不凍結場上時間 |
| 格擋持續扣氣 | 無 |
| 維持格擋回氣 | 無 |

- **攻擊實際命中格擋才扣氣；揮空、躲開或尚未命中不扣氣。**
- 同一次施法的多段攻擊最多扣氣一次；每次獨立普攻各扣 $0.5$ 格。若某段未格擋、後續段才格擋，於首次成功格擋該施法時扣氣。
- 同一次施法只在首次成功格擋時產生防禦停頓；不同施法碰上既有停頓也不延長，停頓期間不妨礙下一次格擋傷害結算。
- 防禦停頓期間可以解除格擋意圖，但不能開始其他操作；後續命中是否格擋，依當下意圖與狀態判斷。
- 剩餘傷害仍扣護盾或生命，可能落敗；不觸發一般受擊僵直。
- 只有控制、沒有傷害的直接攻擊，成功格擋也扣氣；持續地面領域不是可格擋的直接攻擊，不會因人在領域中而扣氣。
- 不區分上、下段，不採完美格擋。空中、受擊僵直、出招與失衡期間不能格擋。

### 閃避

- 無獨立翻滾、衝刺或無敵閃避鍵；走位、跳躍、蹲下不耗氣。
- 蹲下能完整躲過穿雲槍；不能蹲躲火球術、地走焰、寒冰彈或牽引球。
- 跳躍能避開地面波與地面定身，也能在適當時機越過直線彈或光束；碰撞仍依實際高度判定。
- 空中不能施法與格擋，需掌握落地時機；跳躍不是通用無敵。

- 用盡氣量的當次施法仍可完成，但可能被打斷；已生效的護盾、領域不因失衡消失。
- 觸發失衡的當次命中仍按格擋減傷；歸零後的其他命中不享有格擋，包括同一模擬步中排序在後的命中。
- 已在失衡中的零氣不重複觸發／刷新失衡。

### 大招

- 只有地面、滿六氣、已解鎖且冷卻完成時可開始施放。
- **同一局可重複使用，所有大招冷卻皆為 $30\,\mathrm{s}$。**
- 開始施放立即扣氣、開始冷卻與失衡；遭打斷不退款，不縮短冷卻。
- 失衡從開始施放時計算，不等大招效果完成才開始。
- 加賽延續解鎖與冷卻；平手重賽重新等待開戰後二十秒。

## 七、普通技能

### 共通設定

- 準備從伺服器接受指令開始，不包含真人手勢與辨識時間；準備完成才生成效果。
- 全部只在地面使用；除另有註明，效果生成後有 $0.25\,\mathrm{s}$ 收招。下表收招均為 $0.25\,\mathrm{s}$。
- 飛行物無重力、無追蹤、無加速，沿固定方向等速移動；散射星保留各自角度。
- 飛行物於命中、被消除、越界、到達最大路程或最大壽命時消失，取最早者。圓形判定尺寸與可見核心一致，外圈光暈不加入判定。
- 普通直線彈從前方距角色中心 $64\,\mathrm{px}$ 生成，初始重疊也要判定命中，不得跳過近身目標。
- 每枚普通飛行物只能命中一次；同一施法對同一目標的總命中上限另依技能規則。
- 指定位置技能沒有鎖定距離上限，可標記場內對手的橫座標；位置在開始施法時固定。
- 地面矩形技能不傷害空中角色，另有完整高度判定的爆炸除外。

- 不屈法陣剩餘額度不足時，當次只減免剩餘額度，不能超過上限。例如只剩 $40$ 額度、原傷害 $100$，該次承受 $60$，然後效果結束。

- 位移期間不能主動水平移動、起跳或相位步；仍可保留格擋意圖。可在一般僵直結束後普攻或施法，但強制移動仍繼續；不屈法陣生效則取消。
- 牽引球以命中時施法者位置作固定終點參考，最多拉到雙方碰撞框邊緣相接，中心距離 $64\,\mathrm{px}$；不追蹤後續走位，不拉過施法者。若原本不足合法間距，不追加拉近。
- 中心完全相同時，推開方向採該次施法鎖定方向。
- 相位步是自身位移，不是強制位移，不觸發推拉免疫，但受定身限制。

### 地面領域

- 緩速領域與重力井只影響接地角色；角色腳底的水平區段 $[x-32,x+32]$ 與領域有正長度重疊就生效。
- 離開地面領域或跳起，領域來源緩速立即解除，無額外殘留時間；其他已附加的定時緩速仍保留，包括空中。
- 領域在原生成位置固定，不跟隨施法者；越出場界部分裁切。
- 同一玩家同種領域最多一個；新領域生效時取代舊領域，不疊加。
- 淨化免疫期間不受領域緩速；免疫結束仍在區內即再次受影響。

### 控制與受擊

- 緩速只影響水平主動移動，不改變跳高、重力、辨識確認時間、準備或收招。
- 多個緩速各自計時，只採當下最強效果，不相乘；較強結束後，尚未到期的較弱效果仍有效。
- 定身禁止地面移動、跳躍與位移技能，但仍能普攻、格擋或施放其他技能。淨化、聖域與不屈可在定身中開始。
- 定身與強制位移共享控制互斥：已有其中一種時，不新增另一種，也不刷新正在執行的控制。
- 任何定身／強制位移結束後 $2\,\mathrm{s}$ 內免疫新的定身與強制位移；淨化或其他解除造成提前結束也開始此免疫。
- 控制免疫不阻止傷害或緩速；格擋小幅推退也受同一免疫限制。
- 一般未格擋命中造成 $0.2\,\mathrm{s}$ 受擊僵直，同一段不被後續命中延長；恢復後 $0.3\,\mathrm{s}$ 免疫一般僵直。
- 一般僵直無額外擊退；只有明列推拉的技能造成位移。護盾全吸收傷害仍可造成僵直與控制。
- 普通／大招的所有直接傷害皆使用上述僵直；被格擋或處於僵直免疫時不新增僵直，仍結算傷害。
- 只有持續緩速、沒有命中傷害的領域，不造成一般僵直。

## 十、技能交互與結算規則

### 出招與打斷

- 開始施法就消耗氣並進入冷卻，遭打斷不退款。
- 準備期間遭有效命中且該次確實新增一般僵直時，取消待生成效果；僵直免疫時仍扣血，但不因此打斷。
- 收招期間受擊不取消已生成效果；僵直與原收招各自計時，兩者都結束才恢復操作。
- 已生成的飛行物、爆炸標記、護盾與領域保留。準備期間的預警不是已生成攻擊，被打斷就撤回預警。
- 已生成的短暫範圍攻擊也持續到自身窗口結束；普攻有效窗口則依普攻取消規則。
- 同一玩家同技能的普通飛行物尚未全部消失，不能再次施放該技能；反射後仍列入原施法的物件清單，直至真正消失。
- 不必等持續效果結束才能恢復操作；但仍受收招、僵直、失衡與其他限制。

### 防守交互

- 所有直接攻擊與普通揮擊皆可地面格擋，沒有破防普攻。
- 攻擊被格擋不附加緩速、定身、拉近或一般僵直；只有明列格擋小幅推退的招式例外。
- 地面領域緩速不能靠格擋取消；飛行物不互相抵銷。
- 飛行物交會的處理順序以實際路徑上的最早接觸為準；同時接觸時依風障消除、鏡返反射、角色命中的順序處理，不能隔著先命中的角色讓後方牆補擋。
- 風障、鏡返不保護大招、地面波或爆炸；鏡返是反射，風障是消除，兩者均無額外傷害。

### 傷害計算

設本次原始傷害為 $D$，不屈剩餘額度為 $B$，護盾為 $S$。

- 成功格擋：$D_{\text{承受}}=0.2D$，不消耗不屈額度。
- 未格擋且不屈有效：$R=\min(0.6D,B)$，$D_{\text{承受}}=D-R$，$B\leftarrow B-R$。
- 未格擋且不屈無效：$D_{\text{承受}}=D$。
- 護盾吸收：$A=\min(S,D_{\text{承受}})$；新護盾 $S'=S-A$，生命扣除 $D_{\text{承受}}-A$。

傷害先減傷、再扣護盾、剩餘扣生命。格擋與不屈不相乘；不屈額度統計護盾之前實際減免的傷害。格擋仍扣氣。生命與護盾最低為零。

- 生命、護盾與減免額度保留到小數後兩位，不逐段四捨五入成整數；勝負比較使用內部實際值，介面也顯示必要的小數。
- 氣量以整數刻度處理：每格 $120$ 單位；每次格擋扣 $60$ 單位；正常回氣每個模擬步恢復 $1$ 單位，可精確表示每秒半格。
- 同一模擬步先完成可在該步生效的技能效果，再判定交會；被當步新攻擊命中時，已完成準備的效果不倒退取消，尚未完成的準備仍可被打斷。
- 同時多次命中同一目標，按交會時間、施法開始步、施法編號、段編號排序，逐次扣護盾／氣量與檢查控制；全部目標傷害結束後才作死亡判定。
- 定身、一般僵直與推拉免疫分開管理；同時控制衝突採上述順序的第一個合法控制，其餘只結算傷害與可附加緩速。

詳細規則以本整合文件第三部分為準；本節防止把 PVP 的 BO1、無回血與選技規則錯套到單人模式。

- 技能圖鑑：15 普通技能、9 大招與共通普攻，數值由同一技能註冊表生成；不洩露其他房間隱藏配置。
- 練習：任選三類各一普通技能及一大招，無選技順位、無局時、無排行榜；假人可站立、格擋、蹲下、循環跳躍。輔助開關依補充規格，不能進正式模式。
- PVE：一名敵人依序出場，玩家一命到底；每敵人 90 秒，超時結束，不加賽、不重賽。玩家與敵人同時死亡不計擊敗。
- 玩家存活擊敗敵人後回最大生命的 25%（250 血）、增加 3 格氣，分別不超過 1000 血、6 氣。死亡不發獎勵；冷卻與累計大招解鎖延續，清除失衡及暫時效果。間歇和倒數不額外恢復資源。
- PVE 配置整次鎖定，AI 配置公開；不使用 ABBAABBA 或雙方普通技能禁重複限制。AI 不得跳過核心限制，反應與難度依補充規格。
- PVP、練習與PVE均可選鍵盤或辨識器；鍵盤不需主機開啟內測。Python模擬仍限內測；排行榜資格依第三部分記錄來源，使用鍵盤或途中切換不列原正式手勢榜。
- 單台主機本機榜按版本分組，關機重啟保存已完成成績；不要求多機同步。

上述例外之外，碰撞、傷害、耗氣、收招、控制、反射、輸入重武裝與安全逾時均共用原規則與同一戰鬥核心。

## 十五、numeric-v2 平衡與幾何契約

以 1 格約 100 原傷害作攻擊基準。純攻擊技能理論全段在 100–120 傷害／氣；難以完整命中、可明確反制的招式靠近上緣。攻擊大招全段在 100–110／氣。控制技能因有額外收益，其直接傷害 80–95／氣；控制大招 80–90／氣，並削弱原控制時長。不能讓同等直接傷害又帶強控制而全面優於攻擊技能。

防禦／無傷害技能不適用「直接傷害／氣」相等：護盾术為 120 護盾／氣，聖域為 100 護盾／氣，寂靜為 80 護盾／氣另加局部清彈，不屈最多 90 減免／氣另加控制免疫。鏡返、風障、淨化、相位與緩速領域都是情境收益，不宣稱它們有已驗證的等值 DPS；其成本、成功率與避免傷害須在實機記錄。無傷害領域降至 1 氣、320 寬、30% 緩速、3 秒以降低低回報成本與覆蓋。

長距離移動飛行物的「路程」不是瞬時覆盖範圍。所有前方技能以鎖定位置的前緣為原點，場外部分裁切；圓形使用圓對矩形，不把外接矩形當成判定。星隕、寒霜、風暴起始位置固定，施放後不追踪、不跟著施法者移動。

非接地判定的攻擊不存在「跳躍一定躲掉」：風暴範圍上緣 570，高於最高跳腳底 676，原地跳必須仍可能被命中；新星最高跳也可能相交。接地技能只命中接地目标，即使空中框與地面矩形重疊也不算命中。延爆与流星可命中空中，不能以動畫飛高假定安全。

目前正常走速、20%／30%／40% 緩速對應 320／256／224／192 px/s；緩速可以讓走離預警來不及，因此仍要依招式選跳躍、格擋或淨化。任何反應餘量均未包含實測辨識／傳輸延遲，不能據此保證真人能躲。

雙人同時落地重疊時：按落地前最後一個非重疊的相對左右順序（沒有則上一個 tick 的中心排序，相同則固定紅左藍右），以中心中點分配到相距 64 的兩個位置；整對平移到合法場界內，保持距離64。只有一方落地時依原單落地者規則。防止順序處理偏差與場邊死鎖。

掃掠碰撞、初始重疊、窗口末步、同 tick 傷害及格擋扣氣仍須按實際產品核心驗證。不得用本次理論比率推算真人命中率或直接宣布所有技能平衡完成。

失衡 numeric-v2：3 秒結束只回 1 格，避免原本 3 秒回 2 格（每秒 0.667 格）高於自然回氣每秒 0.5 格而鼓勵故意耗盡。3 秒固定期限、其間禁技能與格擋不變；這仍是最低恢復保障，名義耗氣與長期淨支出要分開統計。

## 一、交給 Codex 的任務

未來明確獲授權製作時，依本整合文件第一部分的遊戲規則及以下產品規格，製作兩個可獨立交付的專案：

- **`gesture-arena`**：可在主持人筆電執行的競技場伺服器、玩家遊戲網站與主持人控制／觀戰介面。
- **`gesture-player`**：發給所有學員的共用 Python repo，提供攝影機、錄製、特徵、模型檔案、測試介面及競技場連線；**特徵正規化與KNN留給學員實作；濾波為選做**。

這是可執行產品的製作要求，不是只做 UI、原型、單機演示或技術提案。可以分階段開發，但最終需連通玩家 repo 與真正的競技場伺服器。

### 參考文件與優先順序

- `gesture_arena_complete_rules.md` 是遊戲規則、全部技能、數值與戰鬥時序的唯一依據，地圖邏輯尺寸固定為 $1920\times1080\,\mathrm{px}$。
- 本文件定義產品架構、操作流程、連線協定、repo 分工及驗收，不另改傷害、冷卻或技能平衡；`arena_modes_and_acceptance.md` 定義單人模式例外、新增功能及更具體的接口／驗收。
- 遊戲數值已收錄於本整合文件第一部分，不因未附同名分拆文件停止工作；若本文件本身仍缺少必要數值，列明缺項，不自行猜測。
- 發現文件真正衝突時，提出具體衝突；一般實作選擇可自行處理並記錄，不能用方便實作為理由刪掉玩法。
- 下方程式碼與路徑是應交付的接口／結構規格，不代表目前已有程式完成。

### 已確定的活動條件

- 所有學員拿到相同的玩家 repo，使用自己筆電與鏡頭，錄製自己的十類手勢。
- 十類手勢只代表固定動作；姿勢可自選。`NONE` 是無有效指令狀態，不要求一定錄第十一種姿勢。
- 辨識在玩家筆電執行，不上傳攝影機影像、真人資料或整份辨識程式到競技場。
- 目前只使用一台主機；每間 PVP 房兩位真人，單人練習／PVE 房一位真人與假人／電腦。混合房間容量依補充規格驗收。
- 主持人以 HDMI 接大螢幕觀戰，不需要影片直播、OBS、音效或付費 AI API；需要本機持久保存的 PVE 排行榜。
- 本機區網部署為主要交付方式；學校網路、公網 IP、網域與 Tunnel 的選擇暫不列入製作阻礙。
- 在正式實機測試前，不宣稱所有鏡頭、作業系統或網路已驗證相容。

## 二、架構與技術選型

| 部分 | 技術／責任 |
| --- | --- |
| 玩家與主持人網站 | React、TypeScript、Vite，繁體中文介面 |

## 四、競技場介面與角色權限

### 必須提供的畫面

| 畫面 | 必要功能 |
| --- | --- |
| 首頁／加入 | 暱稱、建立 PVP 房間、以房間碼加入藍方或觀戰；滿席顯示原因，不直接開打 |
| 房主控制台 | 建房者管理自己的房間：準備狀態、開始選技、開戰、暫停、重連確認、重賽、下一場；不管理其他人的房間 |
| 玩家準備區 | 本人席位、控制來源、配對碼、辨識器狀態、最新標籤、輸入測試、準備按鈕 |
| 選技 | ABBAABBA、類別限制、普通技能禁重複、私人大招選擇與確認 |
| 戰鬥 | 完整遊戲畫面、本人操作狀態、必要拒絕原因 |
| 觀戰 | 公開 HUD、大招資訊遮蔽、全螢幕，沒有玩家控制權 |
| 結果 | 勝負／平手、加賽或重賽流程；保持房間可繼續換場 |

- 主持人可在筆電開控制台，另開觀戰視窗拖到 HDMI 螢幕；兩頁使用同一場伺服器狀態。
- UI 提供全螢幕與等比例縮放，保持完整場地，不裁切；大螢幕讀得清楚。
- 玩家開戰前可測試全部標籤；測試結果顯示在準備區，不改變正式比賽生命與氣量。
- ESC 在正式比賽不直接重置世界；顯示退出確認或關閉本地選單。只有主持人可重賽／重開。
- 以真實伺服器房間與網路狀態驅動畫面，不能用假連線或固定測試資料冒充完成。

### 自助 PVP 房間與管理範圍（本次確認，覆蓋舊主持人敘述）

- 所有使用者都可建立 PVP 房間，不需主機主持人替每場開房。建立者預設取得紅方與只限該房的房主憑證；受邀玩家輸入房號加入藍方，一名觀戰者可加入唯一觀戰席位。單純瀏覽首頁／圖鑑不會加入同一場戰鬥。
- 房號只用於定位及邀請，不授予管理權。房主憑證与玩家／控制器憑證分離；建房者兼具紅方玩家身分與房主權限，隱藏大招依玩家身分投影，觀戰資料仍不可洩露。
- 文中一般 PVP 的「主持人」管理權限改解讀為該房房主；既有準備、選技、開始、暫停、重賽流程保留，由房主操作，不由全班共用的主持人逐場指定席位。普通觀戰者無管理或控制權，房主只可管理自己的房間，不得管理其他人的单人／PVP房間或清除全主機排行榜。
- 觀戰名額按伺服器有效觀戰 session 計算，第二名觀戰者加入須收到穩定的滿席錯誤；離開與重連須清楚回收／恢復席位，不能靠開新頁繞過容量。一個有效觀戰視窗可輸出 HDMI，不增加第二個觀戰席位。
- 玩家透過網站與本機辨識器加入同一房間並綁定同一席位；每房戰鬥狀態、matchId與廣播分離。伺服器對房號、權限及席位作驗證，不只靠前端頁面分開。
- 全主機榜單維護屬伺服器維護者權限，與可由任何人取得的房主憑證隔離；可保留原規格的本機維護 CLI。若保留全主機管理網頁，須另以主機私有管理憑證授權，不能以建立任一房間取得。
- 此次不自行決定房主退出後的轉移方式；後續需在房間生命週期中定案。開發不得因房主斷線就把管理權交給任意觀戰者或其他房間玩家。

### 身分與權限

- 房間碼用於找到房間，**不是主持人憑證**。
- 主持人建立房間時取得隨機管理憑證；管理操作需驗證，不因 client 宣稱 `role=host` 就授權。
- 玩家進房後取得席位／玩家 session 憑證；暱稱不是身分證明，同名也不能接管他人。
- PVP 房間固定紅方與藍方各一個玩家席位，以及一個觀戰席位；不提供額外等待玩家名額。席位在伺服器原子配置，滿席明確拒絕；開戰後禁止自行換席。
- 觀眾不能送控制、選技或管理事件。
- 管理與玩家憑證不放入公開 snapshot、QR Code 或日誌；觀戰網址只帶房間識別。
- 本機活動版不要求帳號註冊、電子郵件或外部登入，但仍需上述最小角色驗證。

## 五、房間與比賽生命週期

每房有獨立狀態機，不用 UI 頁面切換代替伺服器狀態。

```text
LOBBY -> DRAFT -> READY -> COUNTDOWN -> PLAYING -> RESULT
PLAYING -> OVERTIME -> RESULT
PLAYING / OVERTIME -> PAUSED -> RESUME_COUNTDOWN -> 原狀態
RESULT -> 同配置重賽 / 返回準備並更換玩家
```

- 每手選技都在伺服器驗證順位、類別與重複限制；選技有 ACK，重複提交只接受一次。
- 起始 A／B 隨機，與紅藍分開記錄。
- 隱藏大招從首次合法開始施放時公開；打斷不撤回公開。平手重賽按遊戲文件保持已公開狀態。
- 倒數不消耗局時、冷卻或解鎖時間。恢復倒數期間也不推進戰鬥時間。
- 開戰需要雙方網頁、選技、控制來源與準備完成；選辨識器者需完成配對及必要算法可用，選鍵盤者不需攝影機、Python工具或算法。鍵盤在正式部署亦可使用，不需開啟內測。
- 玩家網頁或必要控制器失聯才暫停；一般觀眾與主持人觀戰頁失聯不暫停。
- 相同配置重賽可保持原玩家配對；換玩家／換席需撤銷該席位全部舊配對碼與控制器憑證。
- 重賽使用新 `matchId`，所有舊操作不能跨局生效。
- 主機程序崩潰時第一版可重開並重賽，不宣稱具備持久化恢復。

## 六、辨識器與角色配對

### 玩家實際流程

1. 任一玩家建立 PVP 房間，取得房號與紅方席位；另一位玩家以房號加入藍方。觀戰者以房號及觀戰身分加入唯一觀戰席位。單人模式仍由本人建立並取得紅方。
2. 玩家準備區產生該席位的一次性配對碼。
3. 學員啟動本機辨識器，輸入伺服器網址、房間碼及配對碼。
4. 辨識器建立 `/controller` namespace 連線並送配對事件。
5. 伺服器原子驗證並消耗配對碼，建立控制器 session，綁定 `roomId + playerId + seatGeneration`。
6. 兩端顯示同一席位及「已配對」，做手勢或模擬輸入確認網站收到了。

### 配對要求

- 配對碼採隨機六位數字，以字串保存前導零；有效期 $120\,\mathrm{s}$，範圍以房間識別限定。
- 同一席位重新產生配對碼立即撤銷舊碼；競爭配對時只能一條連線成功。
- 每條來源連線的錯誤配對限制為每分鐘五次，錯誤提示不能洩露其他玩家資訊。
- 成功後回傳隨機且至少 $128$ bit 熵的控制器重連憑證，以及伺服器產生的 `sessionId`。
- 已有有效控制器時，不因第二台輸入配對碼就靜默接管；需玩家或主持人確認替換，並撤銷舊憑證。
- 控制器憑證保存在記憶體；選擇本地保存時限於使用者私有設定，不寫入 repo、不顯示完整值。
- 改席位／換玩家／清空房間時遞增 `seatGeneration`，撤銷舊綁定。
- 重新連線驗證憑證並建立新的 `sessionId`；序號可從頭開始，但原 session 的事件不得繼續使用。

## 七、十一個固定輸入與鍵盤相容

| 資料類別 | 標籤 | 鍵盤按鍵 | 類型 |
| --- | --- | --- | --- |
| $0$ | `MOVE_LEFT` | `A` | 持續 |
| $1$ | `MOVE_RIGHT` | `D` | 持續 |
| $2$ | `JUMP` | `W` | 一次，跳躍方向依遊戲文件 |
| $3$ | `CROUCH` | `S` | 持續 |
| $4$ | `BLOCK` | `Space` | 持續 |
| $5$ | `NORMAL_ATTACK` | `J` | 一次 |
| $6$ | `ATTACK_SKILL` | `K` | 一次 |
| $7$ | `DEFENSE_SKILL` | `L` | 一次 |
| $8$ | `CONTROL_SKILL` | `U` | 一次 |
| $9$ | `ULTIMATE` | `I` | 一次 |
| 無 | `NONE` | 放開全部控制鍵 | 解除 |

- 最終一條 session 同時只有一個標籤；鍵盤多鍵按住時採最後按下的有效控制鍵，放開後回到仍按住的上一個控制鍵。
- 禁止瀏覽器按鍵自動 repeat 造成連發；表單輸入與聊天／暱稱欄不能觸發遊戲。
- 網頁失去焦點、隱藏或離開頁面時解除鍵盤輸入；正式辨識器仍由其自身連線維持，不能混用兩個來源。
- 舊手勢及鍵盤轉換都經同一個伺服器 `InputRouter`，不各自重寫規則。
- 玩家準備區常設控制來源選擇：鍵盤／手勢辨識器；預設手勢，每席獨立選擇，不需內測開關。戰鬥中不可直接切换，可在伺服器暫停狀態切換作為備援；清除舊輸入並驗證新來源後恢復，詳見下節控制契約。

### 一次性觸發與持續狀態

- 一次性標籤只在合法進入該標籤時嘗試一次；重複回報同標籤只刷新連線／輸入活性，不重新施法。
- 無氣、冷卻、空中、收招或失衡造成拒絕也算本次已嘗試，不等待條件變好才自動施法。
- 解除／切換持續 $0.1\,\mathrm{s}$ 才重新武裝原一次性動作；停止移動、蹲下或格擋要立即生效。
- 短暫 `NONE` 後立即返回原出招標籤，未達解除時間不得重放；用時間測試而非靠封包數。
- 超過 $0.5\,\mathrm{s}$ 未收到有效新狀態，強制解除；倒數結束／重連後先要求有效 `NONE` 解除，再接受一次性動作。
- 安全逾時不能合成跳躍、攻擊或自動維持方向，失衡與受擊等限制由戰鬥核心另外檢查。

## 八、Socket.IO 協定

初版使用 `protocolVersion: 1`；Socket.IO path 固定 `/socket.io`。瀏覽器使用 `/arena` namespace，辨識器使用 `/controller`。同 origin 下瀏覽器自動使用目前伺服器；Python 填入服務 base URL，不手填 namespace 到 URL 尾端。

### 主要事件

| 事件 | 方向／權限 | 用途 |
| --- | --- | --- |
| `room:create` | 網頁 → 伺服器 | 建立房間並取得主持人憑證 |
| `room:join` | 網頁 → 伺服器 | 加入／觀戰，取得個人 session |
| `room:assign` | 主持人 → 伺服器 | 指定席位，必要時撤銷原綁定 |
| `player:ready` | 玩家 → 伺服器 | 設定準備狀態 |
| `controller:code` | 已入席玩家 → 伺服器 | 申請／更新配對碼 |
| `controller:pair` | 辨識器 → 伺服器 | 配對房間與席位 |
| `controller:resume` | 辨識器 → 伺服器 | 憑證驗證與重連 |
| `controller:unbind` | 本人／主持人 → 伺服器 | 撤銷控制器 |
| `controller:status` | 伺服器 → 本人／主持人 | 配對、失聯、最新標籤與健康資訊；不含私密憑證 |
| `controller:context` | 伺服器 → 辨識器 | 當前 roomId、matchId、比賽階段及控制來源；新局／重賽／恢復時更新，無隱藏技能資訊 |
| `draft:pick` | 當前選技玩家 → 伺服器 | 鎖定一手技能 |
| `match:start` | 主持人 → 伺服器 | 檢查準備後倒數開戰 |
| `match:pause` / `match:resume` | 主持人 → 伺服器 | 暫停／恢復倒數 |
| `match:rematch` | 主持人 → 伺服器 | 相同配置重賽 |
| `match:next` | 主持人 → 伺服器 | 返回準備，可更換玩家與選技 |
| `match:forfeit` | 主持人 → 伺服器 | 斷線逾時人工判負，需指定玩家及理由 |
| `input:state` | 有效控制來源 → 伺服器 | 最新標籤 |
| `client:heartbeat` | 所有客戶端 → 伺服器 | 應用層連線健康；不等同新手勢 |
| `input:result` | 伺服器 → 本人 | 單次動作接受／拒絕與原因 |
| `room:state` | 伺服器 → 分權限客戶端 | 房間、選技、席位及準備資料 |
| `match:snapshot` | 伺服器 → 分權限客戶端 | 戰鬥權威狀態 |
| `match:event` | 伺服器 → 分權限客戶端 | 施法、命中、反射、效果結束與勝負等表現事件 |

### 配對訊息示例

```json
{
  "protocolVersion": 1,
  "roomCode": "ARENA-A",
  "pairCode": "042731"
}
```

成功 ACK 的欄位：

```json
{
  "ok": true,
  "protocolVersion": 1,
  "roomId": "room-a",
  "playerId": "player-red",
  "seat": "red",
  "sessionId": "server-generated-session",
  "controllerToken": "opaque-reconnect-token",
  "matchId": null
}
```

### 輸入訊息示例

```json
{
  "protocolVersion": 1,
  "sessionId": "server-generated-session",
  "matchId": "current-match",
  "seq": 123,
  "gesture": "ATTACK_SKILL"
}
```

- 準備／輸入測試時 `matchId` 為 `null`，只更新測試狀態，不執行戰鬥。
- Python 配對／重連成功後取得完整 `controller:context`；此 namespace 主動接收新局與階段變更，不依賴遊戲網頁轉傳 matchId。
- 倒數／新局時伺服器通知最新 `matchId`，辨識器更新；舊 matchId 在正式戰鬥中一律拒絕。
- session 與連線本身綁定，不能只提交別人的 session 字串就控制他人。
- `seq` 為非負遞增整數；同 session 重複／倒退序號拒絕，不刷新有效輸入時間。session 改變才可重新從零開始。
- 不接受自報 `playerId`／角色座標／氣量／傷害來決定權限或結算。
- 可選 `diagnostics` 放辨識耗時與追蹤狀態，限制資料大小；診斷不影響傷害或戰鬥速度。
- 如包含本機時間戳，只供本機延遲分析，不直接與伺服器時鐘相減，不讓客戶端指定回溯命中時間。
- 未知版本、非有限數值、非法標籤、過大 payload 或不存在 session 都有明確拒絕原因。

### ACK、去重與重新連線

- 加入、選技、配對、開戰與管理操作使用 ACK、`requestId` 及去重；ACK 超時不等於操作一定未執行，重試返回同一結果。
- 不對每一個持續標籤逐包等待 ACK；操作結果按需要另行回報，不堵塞輸入。
- 斷線期間不緩存遊戲輸入、不重播舊攻擊；Python 與瀏覽器都需避免 Socket.IO 自動緩存造成重連後補送。
- 接收完整 snapshot 可恢復顯示；不假設斷線期間所有 event 都被可靠補發。
- state 只保留最新資料；客戶端 backlog 時丟棄舊 snapshot，避免越看越落後。
- 心跳正常但辨識工作無最新結果時，不能持續轉發上一個動作；傳輸工作把過期結果轉成 `NONE`。
- 應用層心跳間隔為 $0.5\,\mathrm{s}$；無心跳達 $2\,\mathrm{s}$ 視為失聯。手勢回報與連線健康分開，普通心跳不刷新有效手勢時間。

## 九、伺服器戰鬥核心與同步

### 模組責任

| 模組 | 責任 |
| --- | --- |
| `RoomManager` | 房間、角色權限、席位與生命週期 |
| `PairingService` | 短效配對碼、token、session 與撤銷 |
| `DraftManager` | 選技順序、類別與重複檢查、私人資料 |
| `InputRouter` | 標籤、單次觸發、持續意圖、序號、逾時與控制來源 |
| `GameCore` | 全部技能、角色運動、碰撞、氣量、控制、傷害與勝負 |
| `VisibilityProjector` | 為本人、對手、主持人／觀眾建立不同資料投影 |
| `SnapshotPublisher` | 同步節奏、序號、完整狀態與顯示事件 |

- 定時模擬每秒 $60$ 步，同步每秒 $20$ 次；用單調時鐘／固定步長 accumulator，不直接把浮動 render delta 當戰鬥時間。
- 不以 `setInterval` 恰好每次準時為前提；有界補步並記錄落後，過載明確顯示，不能無聲改動技能時長。
- 時間、氣量與傷害依遊戲文件的精度處理，無任意逐段整數四捨五入。
- 角色動作狀態與護盾、緩速、定身、免疫、失衡、收招期限分開；不只用一個 enum 覆蓋所有效果。
- 技能資料與幾何、時序集中於 `game-core`；相同參數供繪圖、預警、碰撞與測試使用。
- 飛行物高速移動作掃掠碰撞，包含初始重疊與同步移動角色；不只在每步末尾檢查。
- 跳躍使用能符合遊戲文件解析軌跡的固定步積分方法；不可因積分方式把跳高改掉。
- 同時致死、控制互斥與多段格擋依遊戲文件實作，保留唯一施法／物件／段編號及命中紀錄。
- 清理到期效果、法術、session 與房間；同技能飛行物尚存限制也要處理反射後歸屬變化。

### Snapshot 最小內容

- 協定版本、房間識別、matchId、tick、snapshot 序號、比賽階段與剩餘時間。
- 雙方位置、速度、朝向、姿態、動作、生命、護盾、氣量、失衡與公開控制效果。
- 公開普通技能與冷卻；本人自己的大招資訊；已公開大招的公開資訊。
- 飛行物、領域、預警、效果期限、施法鎖定位置與可繪圖的判定資料。
- 最新接受的輸入序號，供本機移動預測修正。
- 隱藏大招使用未知值，不送其技能 ID、專屬 cooldown、可推知種類的私人欄位。

完整權威狀態只留伺服器；每一條 `room:state`、snapshot、event、診斷與觀戰 API 都經可見性投影，不只靠 UI 藏圖示。

### 客戶端表現

- Phaser 作顯示，不作獨立權威扣血；React 狀態不必每個繪圖幀重新渲染全部畫布。
- 遠端角色初始插值緩衝為 $0.1\,\mathrm{s}$；本機可預測合法水平移動，依 ACK 序號與 snapshot 修正。
- 預測不能自行確認技能成功、命中、傷害、護盾或勝負；法術表現可分辨等待確認與真正生成。
- 遠端位置平滑不改變伺服器碰撞；瞬移、重賽與重連使用明確位置切換，不能長距離錯誤插值。
- 沒有聲音；新增 PVE 排行榜依補充規格；可見特效須能區分技能與預警，不能用完全相同的球冒充所有技能。

### MediaPipe 邊界、原始資料與學員正規化契約（2026-10-09 新增）

- 使用 MediaPipe Hand Landmarker 的預訓練手掌／關鍵點模型執行推論，只取得 21 點座標與 handedness。它不學習玩家的十個指令、不產生遊戲標籤；本工作坊不要求學員訓練關鍵點模型，也不使用 Gesture Recognizer 或 Model Maker 代做手勢訓練。
- `core/landmarks.py` 負責模型呼叫與固定影像方向；`core/features.py` 僅負責接口調度、型別與輸出驗證。正規化計算放在 `student/normalization.py`；資料錄製、特徵預覽、訓練、評估及即時遊玩不得各自重寫。
- `RawHandSample` 使用 Hand Landmarker 的影像座標 landmarks，不混用 world landmarks。每隻手為 `(21,3)` 的原始 x/y/z；附影像寬高、handedness、存在旗標、影像方向／鏡像契約、擷取版本、批次與時間資訊。單手選擇與雙手固定左右槽由共用程式依明列契約建立，不由畫面左右猜測。
- `FeatureResult` 包含 `valid`、`features`、`reason` 與 `featureVersion`；有效 features 是有限數值的 float32 向量，單手 `(63,)`、雙手 `(128,)`。無效時 features 為 null。雙手依左槽63值、右槽63值、左／右存在旗標的固定順序輸出；缺手槽補零，有手槽各自正規化，兩手皆缺時無效。
- 手掌尺度採像素化座標中 wrist(0) 到 middle_mcp(9) 的三維歐式距離；小於10 px須拒絕。學員須處理此條件，共用安全檢查亦須在正規化前拒絕這類原始樣本；安全檢查不輸出正規化特徵、不提供可直接替代學員函式的答案。
- 共用程式驗證原始點形狀、有限數值、影像尺寸及可靠 handedness；正規化後驗證維度、dtype、有限數值與版本。無手、追蹤失敗、例外或非法輸出均由共用程式強制 `NONE`，不允許濾波覆蓋安全解除。
- 原始資料包含足夠 metadata，讓學員修改正規化後可重新產生全部特徵。修改算法、欄位順序或鏡像設定時須更新特徵版本／實作指紋，清除舊快取、重新建立 KNN 資料並評估；不得把不同版本特徵混入同一模型。模型載入檢查當前正規化設定與指紋。
- 學員任務文件說明輸入／輸出契約、幾何概念與邊界條件，提供少量 fixtures 與測試入口；不交付完整正規化答案。角度／距離特徵可作延伸教學，但本版驗收仍使用63／128維契約，改維度須另更新資料與模型版本。
- 驗收分開記錄共用工具與學員算法：正規化／KNN未完成時，仍驗證安全啟動、原始採集、錯誤處理與模擬傳輸；對應算法及真人辨識如實標 NOT_RUN。濾波未選用記錄為「未啟用／選做」，不使直接輸出模式驗收失敗。共用路由可用明確標示的固定輸出stub驗證，但不得視為學員算法或真人辨識通過。

### 選做濾波、固定輸出與介面分工（本次確認）

- Python玩家工具的Tkinter視窗提供「使用學員濾波」開關，預設關閉；開關不放在競技場網頁。關閉時將KNN有效Prediction的固定標籤直接交給共用路由，invalid或NONE輸出NONE；開啟時呼叫StudentFilter.update，輸出仍限十個固定指令或NONE。
- 兩條路徑在同一共用輸出路由合流，經型別／標籤驗證、相機與資料活性檢查後，交給同一網路發送入口。學員只修改student/算法檔，不改網路程式、發送位置、事件名稱、封包、session、序號或回報頻率。
- 共用程式可實作直接取用KNN標籤的路由，這不屬濾波答案：不得在此路徑加入隱藏的多幀投票、確認等待或備援手勢分類。伺服器既有一次性重武裝與安全逾時照常保留。

- 切換模式由共用程式清除舊输出及必要的濾波歷史，先送NONE再處理新結果；不能把切換前的攻擊補送。兩模式維持同一recognizer控制來源，競技場不需要新增濾波開關或不同input:state協定。

### 特徵與不同鏡頭

- 單手為預設；取 $21$ 個手部點，每點三維座標，共 $63$ 個特徵，順序固定。
- 以下正規化步驟是學員實作契約，由 `student/normalization.py` 完成：影像正規化 $x$ 乘影像寬、$y$ 乘影像高、$z$ 乘影像寬；再以手腕作平移原點，以手掌尺度作正規化。錄製後特徵預覽、訓練、測試與遊玩均呼叫同一函式；共用工具不另做一份算法。
- 尺度過小、點非有限或追蹤失敗視為無效，不輸出亂數特徵。
- 不作完整旋轉對齊，避免把原本需要區別的朝向手勢合併；左右手鏡像正規化可設定，設定必須記錄在資料與模型中。
- 預覽可鏡像；辨識處理採固定且可說明的影像方向，不能只鏡像畫面卻暗中換掉訓練座標。
- 雙手模式使用固定左／右槽，各 $63$ 個特徵加兩個存在旗標，總維度 $128$；缺手以零值與旗標區別，不按畫面左右重新排序。追蹤左右不可靠時拒絕該樣本。
- 單雙手模型不能混用；每人仍只錄十個操作類別與輸出一個最終標籤。
- 嘗試共同鏡頭規格 $640\times480$、每秒 $30$ 幀；必須讀回實際結果，不支援時接受合理降級，不強行拉伸。
- 以最新影格處理，等比例顯示；慢鏡頭不能形成堆積影格。時間濾波使用單調秒數，不假設固定 FPS。
- 每位學員用自己的鏡頭錄製並遊玩；換鏡頭後建議重新測試，不宣稱尺度正規化能消除所有光線與畫質差異。

### 靜態手勢限制與採集建議（本次確認）

- 本版正式辨識必須使用靜態手勢：每個指令由當前姿勢的關鍵點特徵分類，不以畫圈、揮動方向或一段時間的動作軌跡作指令。濾波用於穩定與切換，不把此限制改成動態手勢識別。
- 建議十個指令使用彼此明顯不同且容易維持的姿勢，避免主要依靠微小角度差別；姿勢由學員自行設計，不指定必修形狀。
- 以實際遊玩時舒服的鏡頭角度採集即可，不強制多角度、不要求錄滿所有方向。若實際操作會有小幅姿勢變化，可選擇納入；不為了增加樣本刻意快速轉手或混入過渡姿勢。
- 建議避免重要手指互相遮擋，並了解左右手鏡像設定可能合併部分姿勢差異。若兩個指令容易混淆，可自行重設姿勢、補資料或調整算法，再觀察測試结果。
- README 與任務文件將採集方式、數量、批次與獨立測試列為建議，與強制的靜態手勢及接口格式清楚區分。

### 即時攝影機與資料錄製流程（2026-10-09 新增）

- 本工作坊預設採攝影機即時流程：共用程式連續讀取最新畫面，交給 Hand Landmarker 取得關鍵點，再呼叫學員正規化、KNN及共用輸出路由；路由僅在開關啟用時呼叫學員濾波。MediaPipe 不會自行打開攝影機或監看資料夾；攝影機讀取與逐幀呼叫由玩家工具負責。
- 錄製模式在倒數結束後，依採樣上限保存有效原始關鍵點及所選標籤／metadata；預覽與遊玩模式不必保存每張畫面。學員不需要先拍一批照片再放進資料夾。
- Hand Landmarker 也能處理單張圖片或影片，但本版不新增必須交付的照片資料夾匯入功能；若後續另授權匯入，必須使用相同擷取與特徵契約，不能與即時流程各自採用不同算法。
- GUI 將關鍵點預覽、錄製與辨識／遊玩模式清楚區分；未完成學員算法仍可看到即時關鍵點並錄製原始資料，不宣稱已有手勢分類結果。

### 資料、模型與評估

- 採集數量、批次、訓練方式與訓練／測試分配由學員自行決定，不以200筆或三批作必填條件。工具可提供每類約200筆、分批採集及另錄獨立測試資料的可調建議；數量不是準確率保證，不能以未採用建議阻擋訓練。
- 錄製前倒數 $3\,\mathrm{s}$，採樣上限每秒 $10$ 次，無手／無效原始關鍵點不計入。正規化未完成時仍可採集原始關鍵點，GUI 分開顯示原始有效樣本數及可用特徵樣本數；正規化後被拒絕的樣本不得列入可用特徵數。每批記錄鏡頭、擷取契約及特徵版本。
- 原始照片／影片選擇性保存且預設關閉；預設保存原始關鍵點、標籤及重算所需 metadata。樣本以 `.npz`、metadata 以 JSON 保存；正規化完成後可另存版本化特徵快取，KNN 比較的是特徵向量，不是照片像素。
- 建議依錄製批次分訓練／測試，避免相鄰影格混入兩邊；也可由學員自行配置分配方式。工具須如實標示資料用途及評估限制，未保留獨立測試資料時不得把訓練結果稱為獨立測試表現；明確指定為測試的資料不自動加入訓練集。
- `NONE` 可由無手與拒絕門檻產生，也允許可選錄製「非指令／過渡姿勢」測試資料；不強迫把它當第十一個必修手勢。
- 保存 KNN 的訓練資料、設定、特徵版本、手模式與標籤表即可，不必產生神經網路權重。
- 模型載入預設不用任意 pickle 執行物件，NumPy 檔使用不允許 pickle 的模式；載入錯誤維持安全輸入。

### 執行與傳輸工作分離

- UI 在主執行緒；攝影機／追蹤與分類在工作執行緒；連線／心跳獨立執行。
- 傳輸只讀共用輸出路由的最新安全標籤及其本機單調生成時間，不積壓佇列；不使用濾波時採KNN有效標籤，使用時採學員濾波輸出。
- 新結果逾時 $0.5\,\mathrm{s}$、無手或例外時強制 `NONE`，即使網路心跳正常也不能一直送舊 `BLOCK`。
- 直接輸出與濾波模式維持 `JUMP` 或持續操作時均須持續送最新狀態；不僅「有變化才送」，避免被伺服器安全逾時解除。
- 重連後清除濾波歷史、舊輸入、舊 session 與 matchId，取得新狀態後從 `NONE` 開始。
- 正常關閉嘗試送 `NONE`，停止相機與執行緒；伺服器逾時仍是最終保障。

內測模式只能由主機啟動設定開啟，不得由玩家網頁、輸入 payload 或 query string 開啟。開啟時每個頁面與結果持續顯示「內測模式」，整台伺服器產生的挑戰結果都不進正式榜。CLI simulate及模擬控制器只用於內測與自動驗證；正式瀏覽器鍵盤不屬模擬來源、不觸發全主機內測標記。辨識器來源為 `recognizer`、玩家網頁鍵盤來源為 `keyboard`、Python模擬來源為 `simulated`；不提供作弊保證。

## 1. 文件契約與已確認方向

本部分已與遊戲規則及repo製作要求整合在同一份文件；交付本整合文件即可，不需另交同名分拆文件。戰鬥數值以 numeric-v2 的規則文件為準，輸入安全不變；本文件定義新增模式及驗收。PVP 沿用原規則；只有明列模式例外可以覆蓋原規則。

## 2. 模式與入口

首頁提供 PVP、技能圖鑑、練習場、PVE 挑戰、排行榜。技能圖鑑不需加入房間；練習與 PVE 均建立伺服器權威的單人房間，仍使用玩家網頁與同一 Python repo。玩家自行開始單人模式，不需主持人手動指定席位或湊第二名真人。

單人模式真人固定紅方、假人／電腦藍方。仍須取得玩家session；選辨識器時另外取得配對碼并完成配對，選鍵盤則不需要配對。練習與PVE皆保留鍵盤；PVE來源只能在非戰鬥設定階段或暫停時變更，須記錄整次來源歷史與榜單資格。單人房由本人管理；普通PVP房主不能管理他人的單人房，觀眾無控制權。

每次單人重置、PVE 新關或新挑戰都建立新的 `matchId`，防止前一關輸入生效；PVE 另有跨關不變的 `runId`。房間的 `mode` 是伺服器欄位，不能由輸入封包臨時更改。

- 每個技能詳情包含穩定技能 ID、名稱、欄位、耗氣、冷卻、準備、有效窗口／多段時序、收招、傷害、幾何／射程、控制與免疫、反制、打斷和反射等特殊交互。自身效果標明不適用的射程／傷害，不填誤導性零值。
- 使用 `game-core` 技能註冊表供圖鑑、選技、預警、AI 與戰鬥共用；規則版本及資料雜湊可查。圖鑑顯示所有可選技能不代表公開目前對手選了哪一招。
- 每招提供「到練習場試用」，帶入對應欄位；其他欄位使用下文預設配置。玩家已有練習房時更新自己的房間，不把其他玩家拉進來。
- 不要求影片或逐招預錄動畫；在練習場使用真正戰鬥核心試招就是互動示範。範圍與碰撞框可開關。
- 驗收須逐一檢查 25 個條目完整、數值與註冊表一致、搜尋與分類可用、試用能施放正確技能，並驗證圖鑑 API 不回傳他人的私人配置。

## 4. 練習場：打假人

### 配置與控制

玩家可任選三類普通技能各一招及一種大招，不使用 ABBAABBA，也沒有雙方普通技能禁重複限制。預設火球術、護盾術、寒冰彈、星隕光束；若規則正式名稱不同，必須使用註冊表實際名稱與 ID，不能新增同義技能。

假人與真人使用相同生命上限、碰撞框與受擊規則。假人預設站立不反擊；可切換站立、持續格擋、持續蹲下、原地循環跳躍。循環跳躍在落地且可操作後送新的合法跳躍觸發，不增加空中跳。定身／僵直／失衡等限制照常生效，不以動畫直接改姿態。

玩家可設定假人位置，中心 x 限制在合法場界且不得與玩家地面重疊；調整位置、姿態或配置只可在暫停設定狀態。套用設定後清空場上物件、效果、輸入和統計，以新 `matchId` 重建練習，不在飛行物途中偷偷搬假人。

練習沒有勝負及 90 秒局時。任一角色死亡時本次練習停止，顯示統計，由玩家按重置再開始。預設忠實使用正式耗氣、回氣、冷卻和開戰後 20 秒大招解鎖。

### 訓練輔助

提供四個分開的開關，全部預設關閉：玩家無限氣、玩家取消冷卻、玩家立即解鎖大招、假人不死。持續顯示「練習輔助」及啟用項目；不得帶入 PVP／PVE，不得進排行榜。

無限氣：玩家保持 6 格，不因扣氣觸發失衡；準備、收招、空中與受擊限制保留。取消冷卻：不檢查冷卻期限，但不取消一次性重武裝、動作限制和同技能飛行物尚存限制。立即解鎖：只免除首次 20 秒門檻。假人不死：傷害／護盾／控制照常，生命最低保持 1；統計記錄扣血前計算出的傷害，而非靠生命差推算。

可顯示角色受擊框、技能有效框與預警；各有圖例，不能把純視覺殘影標成仍有傷害。提供暫停、恢復、全部重置、只清統計。清統計不重置世界或取消技能。

### 統計

顯示每次命中的技能、施法 ID／段、原傷害、減傷、護盾吸收、生命傷害、格擋與控制結果；累計有效命中、總生命傷害、總護盾傷害及 DPS。

DPS 定義為累計生命傷害除以從首次生命傷害到目前的有效練習時間，暫停不计時；未命中或時間為零顯示「—」。假人不死使用上述計算傷害。清統計後重新計時，不能用每次命中之間的極短時間冒充平均 DPS。

驗收涵蓋鍵盤與真正 Python 傳輸、四種姿態、位置合法性、全部輔助開關及模式隔離；格擋氣耗、控制免疫、掃掠碰撞與正式戰鬥使用同一核心。

## 5. PVE：一命連戰

### 挑戰流程

`CONFIG -> COUNTDOWN -> FIGHT -> INTERMISSION -> COUNTDOWN -> FIGHT ... -> RUN_RESULT`。失聯可從 FIGHT／COUNTDOWN／INTERMISSION 進入 PAUSED，重連後恢復原階段；戰鬥恢復先 3 秒倒數。首關也是 3 秒倒數。

玩家開始前選三類各一普通技能及一大招，整次挑戰鎖定。AI 配置公開，不走雙人選技順序，也沒有跨雙方普通技能禁重複。每關只有一名敵人，不引入多敵目標選擇或多人碰撞。

初始玩家生命 1000、氣量 6 格。敵人每關生命 1000、氣量 6 格，其他戰鬥數值與 numeric-v2 玩家完全相同，不隨關數增加生命、傷害、速度、耗氣優勢或無敵。

玩家生命歸零即結束；不能復活、讀檔續打或重賽同關。玩家與敵人同一步歸零時挑戰結束，該敵人不計擊敗。敵人先歸零且玩家存活，擊敗數加一；清除全部飛行物、預警、領域、護盾、控制、免疫、僵直、收招及當前輸入，雙方回出生位置。

玩家存活過關時，先清除失衡及暫時效果，再以結算後生命加 250、結算後氣量加 3 格，上限分別 1000 與 6 格；只發一次獎勵。保留冷卻剩餘時間和大招已解鎖狀態。清除動作後，回氣等待重新設為 1 秒。死亡包括同時死亡不發獎勵；不得先回血救回死亡玩家。

過關顯示 5 秒間歇及下一名敵人配置，再 3 秒倒數。過關獎勵在進入間歇時一次結算；間歇與倒數全部戰鬥計時凍結，不額外回血或回氣、不降低冷卻。下一關開始需新的 `NONE` 安全解除。

每關 90 秒，不比較生命判勝，不加賽；完成最後有效步後，先檢查玩家死亡，再檢查敵人死亡，仍未擊敗則超時結束。玩家大招門檻按跨關累計有效戰鬥時間 20 秒；每名新 AI 的大招門檻從該關開戰重新算 20 秒。

退出、失聯逾 30 秒未恢復、玩家離開、主機崩潰或管理中止都結束挑戰。只有伺服器判定的死亡／超時結果可進正式榜；主動退出及失聯結果保存為未完成紀錄。若需讓退出也入榜，必須先修改本條，不能由實作者自行改。

### AI 行為契約

AI 在伺服器執行，透過同一 `InputRouter` 送固定標籤，每 0.1 秒刷新最新狀態、每 0.1 秒決策一次。不能直接扣玩家血、跳過耗氣／冷卻、略過重武裝或在不合法動作時強制施放。

AI 只讀公開當前及歷史戰況、自身配置／冷卻與已公開對手資料；不讀相機、未送出的輸入、玩家隱藏大招或未来亂數。預警出現後須經反應延遲才可回應，不能全知零延遲躲招。

| 關數 | 反應延遲 | 防守決策成功率 |
| --- | --- | --- |
| 1–3 | 0.6 秒 | 35% |
| 4–6 | 0.45 秒 | 50% |
| 7–9 | 0.3 秒 | 65% |
| 10 起 | 0.2 秒 | 80% |

這些是初版 AI 參數，非真人難度平衡已驗證。反應延遲以觀察資料緩衝實作；防守機率每次新施法威脅抽樣一次，不每 tick 重抽到必成功。

優先順序：處理可反應的威脅（適當跳躍、蹲躲或格擋）→低生命且有合法防禦技能時防守→合法且能命中的大招／普通技能→近身普攻→調整距離→NONE。地面型預警優先離開或跳躍；只有穿雲槍可用蹲躲。維持格擋最長 1 秒，之後至少解除 0.3 秒，避免永久防守。失衡時只使用合法移動、跳蹲／普攻。

進攻選擇以預估真實判定範圍而非只看技能名稱；面對無合法技能時調整距離，不自動命中。遠程目標距離 400–700 px，近戰僅在普攻合法範圍內出手。遇強制位移／僵直遵守核心限制。

敵人配置按註冊表固定順序：第 n 關的攻擊索引 `(n-1)%5`、防禦索引 `(n+1)%5`、控制索引 `(n+2)%5`、大招索引 `(n-1)%9`。順序使用規則表的列序，不能用不穩定 map 順序。單次挑戰保存 seed 和 AI 版本，所有隨機決策可重現；不要求每次 seed 相同。

### 結果及排名資格

結果包含 runId、匿名 playerId、暱稱、擊敗數、終止原因、有效戰鬥步數／秒、最終生命、規則版本、AI 版本、控制來源及資格標記。暱稱不等於身分；不採每個暱稱只保留最佳，避免冒名覆蓋。

正式手勢榜要求整次挑戰使用辨識器、沒有練習輔助、內測開關或管理改數值；開始時工具聲明必要的正規化／KNN接口可用，若選用濾波，其接口亦須可用。未選用濾波不影響資格。這只表示來自辨識器通道，不能证明封包一定源於真人或學生沒有改程序；本機活動榜不是防作弊認證。相機精確度不由競技場認證。

正式瀏覽器鍵盤可直接使用；結果標示鍵盤或混合來源并保存，依現有規則不列正式手勢榜，不標成整台主機內測。Python模擬仍只能由主機開啟內測後使用，结果標示內測、不進正式榜。伺服器驗證控制来源；Python `simulate` 必須標示 `simulated`，不能假稱辨識器或瀏覽器鍵盤。

排名依擊敗數降序；同分用累計有效戰鬥時間升序，再完成時間升序、runId 字典序。零擊敗可入榜。每次死亡／超時只建立一筆不可由客戶端改分的結果；退出／斷線未完成另列，不參與正式排序。

## 6. 排行榜保存：單台主機

預設本機 SQLite，存放可配置的資料目錄，不在 repo；關機重啟後保留已提交的紀錄，主機當局崩潰不恢復正在進行的挑戰。提交結果與排名資料使用交易及 `runId` 唯一約束，重試 ACK 不重複入榜。不能每次啟動把資料表清空。

正式榜單按規則版本與 AI 版本分組；內測紀錄獨立保存，不提供正式名次。頁面顯示主機名稱、版本、排序方式、前 100 名與本人本次成績（用 session 對應 runId，不以暱稱判斷本人）；查詢分頁大小最多 100。玩家與普通房主只能看榜；伺服器維護者可匯出 JSON／CSV、清榜（若使用管理網頁，需獨立主機管理憑證及確認對話）。備份／匯入提供 CLI，重複 runId 需拒絕或驗證內容一致，不能靜默改分。

暱稱去除首尾空白，1–20 個 Unicode code point，拒絕控制字元；前端作純文字渲染，不能執行 HTML。榜單不保存攝影機、手勢樣本或配對 token。保留所有正式結果直到主持人清除；設定資料容量告警，不悄悄刪除高分。

目前只部署單台主機，不交付多機同步、中央服務或跨主機排行榜。

現有協定尚未交付，新增欄位仍列 `protocolVersion: 1`；日後已有 v1 用戶端則需版本升級與相容策略。生成完整 JSON Schema／TS 型別／Python 型別及跨語言 fixtures，不只實作此處名稱列表。

| 事件 | 權限與用途 |

| `solo:create` | 玩家建立 PRACTICE 或 PVE 房間，取得 session；回傳房間上限錯誤 |
| `solo:configure` | 本人，非戰鬥階段配置；PVE 開始後不得改 |
| `practice:start/reset/pause/resume` | 本人，只限練習；reset 產生新 matchId |

取消固定四個運行房間的產品限制；任何使用者可建立獨立房間，PVP 每房紅藍各一人及一個觀戰席位。單台伺服器仍共用 CPU、記憶體與網路，容量由可配置的資源限制與實測決定，不宣稱房間無限；超過主機配置容量須明確拒絕。基礎負載驗收至少同時1間PVP、2間練習、1間PVE，每房至多一個觀戰席位；這是測試基準，不是四房硬上限。報告另記錄實測穩定房間數，活動規模超過基準時須依預期並行數追加測試。結果房不算運行戰鬥房，但仍計入房間資料與連線資源；空的單人房斷線30秒後終止，結果房10分鐘無活動回收，排行榜結果不隨房間回收刪除。

## 8. 補齊原規格的實作歧義

- 所有期限使用整數模擬 tick：準備 N 步，於開始 tick + N 生成；窗口用左閉右開區間 `[生成tick,生成tick+N)`，對應 N 次判定，冷卻到期 tick 可接受新出招。到期、輸入、運動、效果生成、碰撞、死亡、發布的順序須寫進核心說明與邊界測試。
- 一次性重武裝以每個一次性標籤記錄離開時間，持續離開 6 步才重新武裝；A→B 可立即嘗試此前已武裝的 B，不需額外等 6 步。暫停／倒數不推進此戰鬥計時，恢復時強制 NONE 重新解除。非法版本／序號不能解除或重武裝。
- 玩家瀏覽器重連需獨立的 playerToken，與主持人、控制器 token 分離；取得新 session、撤銷舊 socket。token 不放網址，刷新可存本機私有 sessionStorage；觀眾不能借玩家暱稱恢復席位。規定 room:resume、有效期與錯誤碼於 protocol.md。
- 主持人管理憑證以伺服器程序生命周期有效；管理頁重連後验证同憑證。主機崩潰後建立新房與憑證，不承諾舊憑證恢復。
- 手掌尺度明確為像素化座標中 wrist(0) 到 middle_mcp(9) 的三維歐式距離；小於 10 px 拒絕。此閾值是第一版可版本化配置。左右手正規化先以固定影像／handedness 契約判斷，再對相對手腕的 x 鏡像；雙手槽与預覽鏡像無關。提供不包含完整算法的固定輸入／預期輸出 golden fixtures，供學員驗證 63／128 維、手腕原點、尺度不變性、左右手模式與缺手旗標；未完成 TODO 時不得把正規化功能標 PASS。
- StudentKNN 的 predict 接受一筆 `(D,)` float32 特徵；fit 接受 `(N,D)` 與 `(N,)` classId 0–9。Prediction 包含 label（固定標籤或 NONE）、valid、nearest_distance（無預測可 null）、vote_ratio（0–1）。Filter 時間為本機單調秒，reset 後不保留輸入。禁止用完成的正規化／KNN／濾波答案作共用交付。
- 教學 TODO 不等於工具缺陷；未完成算法時，安全 GUI、原始關鍵點資料採集、算法缺漏提示及模擬連線須驗收通過。真人辨識驗證需要學員或用户提供已完成算法及自己的資料，不能为了過測試偷偷補解答。
- 資源準備有明確清單及雜湊；第三方授權与本地保存路徑寫入 NOTICE。離線驗證必須拔除外網但保持區網，觀察無 CDN／模型下載請求；依賴安裝不要求離線完成。
